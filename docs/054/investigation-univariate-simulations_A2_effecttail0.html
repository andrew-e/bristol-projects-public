Simulation study of EBMF programs

This vignette evaluates empirical Bayes matrix factorisation (EBMF) programs against synthetic data with known ground truth. It is organised around input versions rather than generative parameter axes: the same simulation, EBMF, and program-validation pipeline is run on versions of the input that differ in how much the planted modules share.

Each version is generated by simulate_trait(), which produces a trait object (the target trait plus driver and background traits) with known ground truth. The total number of SNPs is set via n_coloc_groups, and the total number of traits (rows) via n_traits. Planted modules occupy disjoint SNP sets, so any module overlap comes purely from the trait space: a fraction trait_overlap of each module’s driver traits is shared with the other modules, and a shared trait’s effects are correlated across the modules it drives (trait_effect_corr), but not identical unless trait_effect_corr = 1. Increasing trait_overlap should therefore make EBMF programs increasingly overlap and the planted modules harder to tell apart.

The generative parameters are calibrated to the messy marginals of a real pleiotropy matrix so the simulations are not trivially easy:

  • Every observed cell is a significant hit: background and spurious cells are drawn as sign * (min_abs_z + Exp) with min_abs_z = 4.5 (the approximate floor of real coloc z-scores), and noise is encoded as absence (NA) rather than as small observed values.
  • Driver effects are heavy-tailed across traits (effect_tail), with a minority of cells disagreeing with the target-trait orientation (p_negative = 0.05), matching the ~20% of negative cells seen in real oriented matrices.
  • Background trait densities are heavy-tailed per trait (background_sparsity_sd), so most background traits are observed at only a handful of SNPs while a tail is dense — reproducing the real per-trait sparsity distribution.
  • n_hub_traits pleiotropic hub traits are planted as dense, mostly positive rows observed at a large fraction of SNPs, creating the global baseline similarity and mega-factor structure that competes with the planted modules (real matrices contain a core of such highly pleiotropic traits).
  • The target-trait row is dense and significant at every SNP (target_pattern = "dense"), as real target rows are after orientation.

A fraction p_molecular of the background traits is molecular (gene-annotated eQTL-like traits) and observed with per-SNP probability p_active_molecular, which is much sparser than the phenotype traits’ density. The molecular fraction of each module’s drivers is set separately by p_molecular_drivers, so a module can keep a dense phenotype driver core even when the background is almost entirely molecular — if every driver in a module were a sparse molecular trait the module would be unrecoverable.

For every version, the identical battery is run: run_univariate_clustering() fits EBMF and keeps overlapping soft programs, and summarise_ebmf_programs() filters programs by lFSR, loading magnitude, internal coherence, and trait-subsampling stability. The key output is a per-program table in which each validation check is its own column, so it is immediately visible which check failed for each program:

  • size — at least min_module_size filtered SNPs (n_snps_filtered).
  • internal_sim — mean internal SNP similarity >= min_mean_internal.
  • connectivity — pair connectedness >= min_connectedness.
  • stability — top-loading SNPs recovered with replication >= stability_threshold under trait subsampling.

A program is valid only when every check passes. Because the input now has realistic marginals, recovery is expected to be partial and noisy: the validation gates sit at the same levels that separate real modules from background, so only a subset of the discovered programs should be valid, and the pass rates below are the meaningful output for comparing input versions. The analysis settings below are fixed across versions; only the generative input changes.

Notes for interpreting runs

  • module_recall and coverage preserve overlapping valid EBMF memberships.
  • Planted modules occupy disjoint SNP sets; all module overlap in these simulations comes from shared trait drivers (trait_overlap), with correlated (trait_effect_corr) but non-identical effects, so the modules read as “different SNPs + overlapping trait signatures”.
  • The generative marginals are calibrated to a real pleiotropy matrix: every observed cell is a significant hit (min_abs_z), driver effects are heavy-tailed across traits (effect_tail), a minority of cells disagree with the target orientation (p_negative), background densities are heavy-tailed per trait (background_sparsity_sd), and n_hub_traits pleiotropic hubs create a global baseline factor. With this difficulty level, recovery is expected to be partial and noisy — that is what makes the per-check pass rates informative.
  • ari_all and ari_structured use each SNP’s strongest assigned program as a hard projection, so they remain conventional partition metrics.
  • factor_strength and factor_strength_per_snp are reported scores only; they do not currently filter programs.
  • lFSR and magnitude thresholds determine assigned SNPs before coherence, factor-strength, and posterior-evidence calculations.
  • Stability is run only for programs that pass the size and internal-coherence checks; the stability column shows n/a for programs that were not re-checked.
  • Molecular traits are gene-annotated and much sparser than phenotype traits. Sparse molecular background traits frequently fall below min_snp_signals and are dropped before matrix construction, so n_traits is a nominal matrix size rather than the number of traits that survive to clustering.
  • The null version keeps n_hub_traits = 0 so it remains a pure structural null (no global factor to latch onto); the hub structure of the module tiers is the thing being tested against.
