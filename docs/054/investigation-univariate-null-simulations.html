Null simulation study of EBMF programs

This vignette evaluates empirical Bayes matrix factorisation (EBMF) programs against pure-null synthetic data: K = 0, so no modules, driver SNPs, or driver traits are ever planted. Each simulation is generated by simulate_trait() with only the target-trait row plus unstructured background traits. The pipeline — run_univariate_clustering() followed by summarise_ebmf_programs() — is byte-for-byte the same battery used in the module simulations (investigation-univariate-simulations.html); the analysis settings are also identical. The only difference is that EBMF is now trying to discover programs in data where the only structure is randomness.

The four validation checks are exactly the same gates used on the real pipeline:

  • size — at least min_module_size filtered SNPs (n_snps_filtered).
  • internal_sim — mean internal SNP similarity >= min_mean_internal.
  • connectivity — pair connectedness >= min_connectedness.
  • stability — top-loading SNPs recovered with replication >= stability_threshold under trait subsampling.

A program is valid only when every check passes. Under a true null, any program that passes all four checks is a false discovery, so the per-check pass rates below are false-discovery rates: they show how often each gate (and the pipeline as a whole) is fooled by random background. background_absorbed is the SNP-level analogue — the fraction of background SNPs pulled into valid programs.

Because K = 0, the module-only generative parameters (module_sizes, overlap, n_traits_per_module, trait_overlap, driver_sharing, p_structural_zero, p_spurious, effect_tail) are inert and are not exposed here. The active axes of background realism are p_active_background (how often a background trait is observed at a SNP), background_sparsity_sd (heavy-tailed per-trait density variation), background_effect_scale (background magnitude relative to effect_size), noise_sd (per-cell noise), and n_hub_traits (dense pleiotropic rows that create a shared global factor). Each version below holds everything else at its realistic baseline and varies one axis.

Null versions

Every version plants no modules (K = 0); the versions differ only in the background realism parameter being stressed, with everything else at its realistic baseline. The hub_traits version is deliberately not a pure null: it plants dense pleiotropic rows so EBMF has a real shared global factor to latch onto, testing whether such a mega-factor reads as false programs.

Notes for interpreting runs

  • Under a true null (K = 0, no hub traits) any program passing all four validation checks is a false discovery; the valid column is the pipeline-level false-positive rate.
  • n programs is the number of EBMF programs surviving the lFSR/magnitude membership gate, before any validation check is applied. valid programs is how many of those pass every check.
  • background_absorbed is the fraction of background SNPs placed into valid programs. Because there is no planted structure, every background SNP is genuinely background, so this is the SNP-level false-discovery rate.
  • p_structural_zero, p_spurious, effect_tail, and the module/driver parameters are inert when K = 0 (they only act on driver rows), so they are not exposed here.
  • With p_active_background = 0 every background trait is dropped by the min_snp_signals filter and the EBMF input reduces to the oriented target row; any factor is then the global one and is dropped by ebmf_drop_global.
  • The hub_traits version is not a pure null: dense pleiotropic rows create a real shared global factor. Hubs observed at more than max_snp_fraction (0.8) of SNPs are dropped as ubiquitous before clustering, so only the moderately dense hubs reach EBMF. This version tests whether a legitimate mega-factor reads as false programs under the validation gates.
  • The four checks use the same thresholds as the module simulations (investigation-univariate-simulations.html), so pass rates here are directly comparable to how well the gates separate real modules from background there.
