Null simulation study of EBMF programs

This vignette evaluates empirical Bayes matrix factorisation (EBMF) programs against pure-null synthetic data: K = 0, so no modules, driver SNPs, or driver traits are ever planted. Each simulation is generated by simulate_trait() with only the target-trait row plus unstructured background traits. The pipeline — run_univariate_clustering() followed by summarise_ebmf_programs() — is byte-for-byte the same battery used in the module simulations (investigation-univariate-simulations.html); the analysis settings are also identical. The only difference is that EBMF is now trying to discover programs in data where the only structure is randomness.

The checks are exactly the same as on the real pipeline:

  • Programs with fewer than min_module_size filtered SNPs are dropped before any check.
  • confidence tier, checked in this order:
    • low when similarity_q >= similarity_q: the member SNPs are no more alike than random SNP groups of the same size. This applies whatever the number of traits, so a low program can simply be set aside.
    • single_trait when the program passes the similarity test but its trait loadings rest on fewer than min_effective_traits effective traits. It is one trait’s hits, which noise produces too, so it needs a closer look rather than being discarded or accepted.
    • high when similarity_q < high_similarity_q and connectedness >= high_connectedness; medium otherwise.
    A program counts as valid when its tier is high or medium.
  • excess_similarity / excess_connectedness (effect sizes against the random groups), factor_pve and replication (trait-subsampling Jaccard overlap) are reported alongside, not used for the tier.

Under a true null, any program of high or medium confidence is a false discovery, so the tier shares below are false-discovery rates: they show how often each tier (and the pipeline as a whole) is fooled by random background. background_absorbed is the SNP-level analogue — the fraction of background SNPs pulled into valid programs.

The single_trait share has its own reading. Null programs almost always rest on one trait, so when the trait count was checked first they were all labelled single_trait. Now a null program is single_trait only if its SNPs also pass the similarity test. The single_trait share is therefore how often noise produces a program that lands in the “needs a closer look” tier rather than in low, where it can be discarded.

Because K = 0, the module-only generative parameters (module_sizes, overlap, n_traits_per_module, trait_overlap, driver_sharing, p_structural_zero, p_spurious, effect_tail) are inert and are not exposed here. The active axes of background realism are p_active_background (how often a background trait is observed at a SNP), background_sparsity_sd (heavy-tailed per-trait density variation), background_effect_scale (background magnitude relative to effect_size), and noise_sd (per-cell noise). Each version below holds everything else at its realistic baseline and varies one axis.

Does this simulation exercise the gates in the regime real data uses them?

The validation gates act on the SNP similarity graph, so what matters is not whether the simulated matrix has realistic per-trait sparsity and magnitude marginals – it is whether the graph those marginals induce resembles a real one. Those are not the same thing, and matching the marginals is not sufficient.

simulated_graph_diagnostics() measures the simulated graph and real_bmi_graph_targets() carries the values measured on the BMI pleiotropy matrix. The row to read first is random_set_pass_rate: the fraction of random SNP sets whose mean internal similarity clears 0.3. On real BMI data that is about 0.94 – a random set of SNPs passes the old absolute gate almost always, which is why that gate carried no specificity. Where the simulated value is near 0, a random set can never pass, so a null simulation study cannot detect an uninformative gate and its false-discovery rate is close to un-failable by construction.

The two generative parameters that move this are background_corr (background traits sharing structure, so they contribute to SNP-SNP similarity at all – at 0 they are independent and random-signed and contribute nothing) and snp_pleiotropy_sd (per-SNP heterogeneity in how many traits a SNP is observed on, which is what brings the median pairwise overlap down towards the real ~3 and produces the sparse SNPs that carry high cosines).

Simulation design (ADEMP)

This null study follows the ADEMP structure of Morris, White and Crowther (2019, Statistics in Medicine 38:2074-2102, ); it is the testing-target companion to investigation-univariate-simulations.html.

Aims. To estimate the type I error / false-discovery rate of the EBMF program pipeline under a true null, and how that rate depends on background realism. This is a stretch-or-break aim: find where the gates are fooled.

Data-generating mechanism. simulate_trait() with K = 0, so only the oriented target row and unstructured background rows exist. The varied factors are p_active_background, background_sparsity_sd, background_effect_scale, and noise_sd, each varied one at a time from the realistic baseline.

Estimand / target. The target is the null hypothesis of no planted module; under it, any program passing all four gates is a false discovery, so the valid rate is the pipeline-level false-discovery rate.

Methods. Byte-for-byte the same pipeline and thresholds as the module study: run_univariate_clustering() then summarise_ebmf_programs(), which drops programs below min_module_size and gives the rest a confidence tier (similarity test, then effective number of traits, then connectedness), with factor strength and replication reported.

Performance measures.

  • n programs: EBMF programs surviving the lFSR/magnitude membership gate.
  • valid programs: programs of high or medium confidence.
  • valid rate = valid programs / n programs (program-level false-discovery rate).
  • background_absorbed = |{background SNPs in valid programs}| / n_background (SNP-level false-discovery rate).
  • Tier rates: the share of programs in each confidence tier (high, medium, single_trait, low). single_trait counts programs that pass the similarity test but rest on one trait: noise that needs a closer look rather than being discarded.

Monte Carlo uncertainty. Each rate is the mean over n_sim replicates (default 3; override with params = list(n_sim = ...) for fast test runs), with the replicate as the Monte Carlo unit. Proportions carry MC SE sqrt(p(1-p)/n_sim) and a 95% Monte Carlo interval; continuous measures carry sd / sqrt(n_sim). Common random numbers are used across null versions, and the per-replicate seed is recorded in the estimates dataset.

Notes for interpreting runs

  • Fast test runs. A production render is long: n_sim = 200 over the 10 null versions is thousands of EBMF fits, and a single null fit is expensive because there are 600 trait rows. To iterate quickly, override params:
    • params = list(quick = TRUE) — smoke test (4 representative versions, n_sim = 3, n_null = 1, no stability, n_traits = 100); about 90 s.
    • params = list(n_sim = 5, n_null = 1, n_stability_rep = 0, n_traits = 100) — full null-version grid with cheap internals and a smaller row count; about 1-2 min.
    • params = list(n_sim = 20) — full-fidelity settings at reduced repetitions (still slow, because of the 600 traits). Lowering n_null, n_stability_rep and n_traits gives the largest speed-up.
  • Under a true null (K = 0) any program of high or medium confidence is a false discovery; the valid column is the pipeline-level false-positive rate.
  • n programs is the number of EBMF programs surviving the lFSR/magnitude membership gate, before any validation check is applied. valid programs is how many of those are of high or medium confidence.
  • background_absorbed is the fraction of background SNPs placed into valid programs. Because there is no planted structure, every background SNP is genuinely background, so this is the SNP-level false-discovery rate.
  • p_structural_zero, p_spurious, effect_tail, and the module/driver parameters are inert when K = 0 (they only act on driver rows), so they are not exposed here.
  • With p_active_background = 0 every background trait is dropped by the min_snp_signals filter and the EBMF input reduces to the oriented target row; any factor is then the global one and is dropped by ebmf_drop_global.
  • The four checks use the same thresholds as the module simulations (investigation-univariate-simulations.html), so pass rates here are directly comparable to how well the gates separate real modules from background there.
  • Every aggregate number is a Monte Carlo estimate over n_sim replicates and is reported with its Monte Carlo SE (ADEMP). Reduce n_sim only for test runs; the MC SE in the tables will show the resulting loss of precision.
  • Replicates use common random numbers: the per-replicate seed (sim_seeds) is shared across null versions and recorded in tier_summary$sim_seed, so the study is reproducible and version-to-version differences are more precise than independent seeds would give.
