Investigation of univariate analysis: BMI

Single-trait SNP program discovery for Body mass index (trait id 1992). Each column of the matrix is a BMI GWAS SNP and each row a background study. Profiles are oriented to the BMI-raising allele, compressed, and factorised with empirical Bayes matrix factorization (EBMF) into overlapping programs. Each program then gets a confidence tier (high, medium or low) from a size-matched similarity test and connectedness.

BMI loci have a strong shared direction: almost every BMI-raising allele also raises weight, fat mass, fat-free mass and other body-size measures. That makes two random BMI SNPs look alike, which hides the structure programs are meant to capture. This vignette fits and filters the programs two ways to see what removing that background changes:

  • Run A: all traits. Only other GWAS of BMI and obesity diagnoses are removed.
  • Run B: body-size traits removed. Run A minus the traits that move with BMI at almost every SNP.

Step 4 compares the two runs’ continuous enrichment of trait categories, tissues and pathways, and Steps 5–7 interpret both runs’ programs side by side.

Step 2: Two runs

Each run builds the pleiotropy matrix from its trait set, factorises it with EBMF (run_univariate_clustering()), and scores the programs (summarise_ebmf_programs()) at the shared settings. Programs with fewer than min_module_size member SNPs are dropped before any check.

A program’s confidence tier comes from a similarity test and connectedness. S is the cosine similarity between two SNPs’ oriented, compressed trait profiles (missing cells counted as 0, the BMI row left out).

  • similarity_q — the mean S between member SNPs is compared with similarity_n_perm random groups of the same number of SNPs from the same run; similarity_q is the BH-adjusted share of random groups at least as similar. It is a significance test, so larger programs pass more easily, and the run’s background similarity sets how hard it is to pass.

  • connectedness — share of member pairs with S >= similarity_threshold.

  • low — similarity_q >= similarity_q: the member SNPs are no more alike than random SNP groups of the same size. This is checked first, so a program that fails it is low whatever its number of traits, and can be set aside.

  • single_trait — passes the similarity test, but the program’s trait loadings rest on fewer than min_effective_traits effective traits (effective_n_traits). A program is defined as multi-trait: a factor carried by one trait is just that trait’s hits, which noise produces too, so it needs a closer look rather than being discarded. Near-duplicate traits each count, so a program spread over several body-size traits is not flagged.

  • high — similarity_q < high_similarity_q and connectedness >= high_connectedness.

  • medium — similarity_q < similarity_q, but not high.

excess_similarity and excess_connectedness (each minus its value in the random groups: effect sizes that do not grow with program size), factor strength (factor_pve) and trait-subsampling replication are reported but do not affect the tier. A program whose SNPs are at least 90% contained in a larger program’s loci is listed under it as a child.

Step 4: Continuous enrichment, Run A vs Run B

Each run’s high- and medium-confidence programs are annotated with continuous loading-based enrichment of trait categories, tissues and pathways (KEGG and Reactome, on the colocalising QTL genes). There is no membership cutoff: every SNP with a finite EBMF loading contributes to every program’s test, weighted by its squared loading, in the regression lm(loading^2 ~ membership) against each annotation’s 0/1 indicator (enrich_program_loadings_trait_categories(), enrich_program_loadings_tissues(), enrich_program_loadings_pathways()). A hit needs both FDR ≤ 0.05 and R² ≥ 0.05. The FDR is computed within each run, across every program tested, separately for categories, tissues and pathways (KEGG and Reactome pooled). R² is the share of a program’s squared-loading variance the annotation explains; 0.05 sits between Cohen’s “small” (0.01) and “medium” (0.09).

Each run is a separate factorisation, so program numbers do not carry over: A3 and B3 are unrelated. The heatmap first matches programs across runs by the overlap of their member SNPs.

Step 7: Pleiotropy of program-unique vs shared SNPs

Because EBMF programs are soft, a SNP can be assigned to exactly one valid program (unique) or to several (shared). If programs capture distinct biological programmes, SNPs that uniquely define a single program should be more specific, i.e. carry a lower pleiotropy score (fewer distinct trait categories and protein-coding genes via coloc groups) than SNPs whose signal is shared across programs. This is tested in each run with get_all_variant_pleiotropies().

Gene pleiotropy has a long tail: most SNPs reach 1–4 genes, while a few reach hundreds. The y-axis is therefore on a pseudo-log scale, which is linear near 0 and logarithmic above it, so the bulk of SNPs stays readable and the tail is squashed rather than cut off. Boxes and medians are unaffected by the scale; the diamond marks each group’s mean.
