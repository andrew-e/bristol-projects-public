Investigation of univariate analysis

Single-trait SNP program discovery: each column is a GWAS SNP for the target trait, each row is a background study (phenotypic or molecular; no collapsing). Profiles are oriented, compressed, and factorised with empirical Bayes matrix factorization (EBMF) into overlapping programs. Programs are then validated with a filtering framework — internal coherence (mean internal similarity and connectedness), factor strength normalised by the square root of the number of filtered SNPs, and trait-subsampling stability — plus descriptive evidence scores (aggregate posterior evidence and factor distinctiveness) before interpretation.

We use Body mass index (trait id 1992).

Step 4: Clustering

The oriented compressed matrix X_star is factorised directly with EBMF (features x SNPs), a global mega-factor is dropped if detected, and each SNP is assigned to the factor with the largest absolute posterior loading among the factors it significantly belongs to.

Step 4.5: Program validation

summarise_ebmf_programs() computes internal-coherence metrics on the SNP similarity graph:

  • mean_internal_similarity — mean off-diagonal S inside the module
  • separation — internal minus external mean similarity
  • connectedness — fraction of SNP pairs with |S| >= similarity_threshold

For EBMF, summarise_ebmf_programs() folds the graph-reliability metrics together with trait-subsampling stability and the descriptive additional scores into a single per-program table with pass/fail flags and an overall status:

  • factor_strength / factor_strength_per_snp — proportion of observed matrix signal attributable to the factor (from its fitted reconstruction), computed on the lFSR/magnitude-filtered subset of EBMF-supported SNPs; factor_strength_per_snp = factor_strength / sqrt(n_snps_filtered). Reported for context only; it does not gate status.
  • replication — trait-subsampling stability: how often the top stability_top_n loading SNPs are recovered when 1 - frac_traits of the traits are held out and flashier is refit (n_rep reruns, run in parallel on cores cores). Because this is expensive, it is only computed for programs that pass the internal-coherence checks; those programs must reach replication >= stability_threshold. Stability should use the same filtered SNP reference sets as the other program-level calculations, and the refitted programs are filtered with the same lFSR/magnitude thresholds.
  • posterior_evidence — aggregate (posterior_stat) of -log10(lfsr) across assigned SNPs. Distinguishes programs dominated by borderline lfsr ~ 0.05 memberships from programs whose memberships carry much stronger posterior sign evidence.
  • max_abs_factor_corr / redundant — maximum absolute correlation of the program’s SNP loading vector with any other program; programs exceeding redundancy_threshold are flagged redundant.
  • max_pair_redundancy / most_redundant_program / redundancy_pass — factor distinctiveness: for each program, the reciprocal SNP containment with every other program (pair_redundancy = min(shared / n_snps_A, shared / n_snps_B) on the assigned membership sets). The program fails (redundancy_pass = FALSE) when max_pair_redundancy >= 0.9, i.e. it captures essentially the same SNP set as another program.

A program is valid if it passes all four filters (size, internal, stability, redundancy); the failure reason is recorded in status.

Step 5: Interpret reliable modules

For each reliable module, rank background traits by module specificity vs the rest of the trait (summarise_module_specific_traits()), then summarise trait-category and tissue enrichments vs the trait baseline, plus pathway hits. specificity = mean |z| in the module / (mean |z| in the rest + 0.1) and abs_mean_z_delta = module - rest highlight traits that are specifically elevated in this module rather than merely large everywhere (which ranking by abs_mean_z alone would over-emphasise). Pathway enrichment is queried across Reactome and KEGG with a separate call per source, and the hits are reported side by side as pathways.

Trait baseline = all SNPs attributed to this trait in the analysis (colnames(S)), using coloc rows for those SNPs only—not the whole GPMap universe. Each module is compared to the rest of the trait (leave-one-out): observed link share vs expected share, with fold enrichment.

Annotation tables show the top elevated categories/tissues even when FDR is not significant; FDR is reported when it passes 0.05.

Each hit is scored with a BH-corrected significance summary, thresholded at 0.05:

  • FDR — hypergeometric test of the module vs the rest of the trait.

The bootstrap CI for the fold enrichment shows how precisely the ratio is estimated; because modules are small, a big ratio built on a few links carries a wide interval that includes 1 (the null), so read the CI together with the FDR rather than alone.

Step 5.5: Continuous loading-based enrichment (comparison)

Steps above gate SNPs into a module with a hard lFSR/magnitude cutoff (program_summary$assigned) before testing enrichment. This section runs them on the same ebmf_result and cg used above, for the same valid_ids programs, so the two approaches can be compared side by side.

Step 6: Pleiotropy of program-unique vs shared SNPs

Because EBMF programs are soft, a SNP can be assigned to exactly one valid program (unique) or to several (shared). If programs capture distinct biological programmes, SNPs that uniquely define a single program should be more specific — i.e. carry a lower pleiotropy score (fewer distinct trait categories and protein-coding genes via coloc groups) than SNPs whose signal is shared across programs. We test that here with get_all_variant_pleiotropies().
